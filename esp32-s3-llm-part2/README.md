# LLM на ESP32-S3, часть 2: 15M параметров из флеша

Llama-2 [stories15M](https://huggingface.co/karpathy/tinyllamas) (15.2 млн параметров, TinyStories) на микроконтроллере ESP32-S3.
Это в 58 раз больше stories260K из первой части. Модель не помещается ни в SRAM, ни в 2 МБ PSRAM,
поэтому 4-битные веса лежат во флеше и читаются через кэш на каждом токене.

Код ко второй части статьи: int4 GPTQ, обрезка словаря, ядра PIE без распаковки полубайтов, двухэтапный классификатор
и самоспекулятивное декодирование.

| Ступень | Что включено | tok/s |
|---|---|---|
| 1 | int8, скалярный C, 1 ядро | 2.96 |
| 2 | int4, скалярный C | 2.31 |
| 3 | + векторные инструкции PIE | 4.01 |
| 4 | + второе ядро | 4.63 |
| 5 | + кэш данных 64 КБ, строки по 64 байта | 5.51 |
| 6 | + автозагрузка кэша | 5.59 |
| 7 | + двухэтапный классификатор | 6.46 |
| 8 | + горячие матрицы в свободной SRAM | 6.56 |
| 9 | + самоспекуляция, k=2 | **9.27** (9.05–9.50) |

Плата ESP32-S3 с 2 МБ quad-PSRAM и флешем 8 МБ. Флеш читается со скоростью около 31.5 МБ/с, и итоговая скорость использует около 89% этой пропускной способности.
Самоспекуляция не меняет текст: при жадном декодировании токены совпадают с обычным проходом бит в бит.

## Что нужно

- плата ESP32-S3 с **флешем 8 МБ или больше** (N8R2, N8R8, N16R8 и т. п.);
- Python 3.9+, `pip install numpy pyserial esptool`.

Готовые образы модели лежат в `blobs/`, прошивки собраны в `firmware/prebuilt/`: ESP-IDF и чекпойнт для запуска не нужны.
Исходный `stories15M.bin` требуется только командам `export` и `analyze`, которые пересобирают образы на компьютере:
[скачать](https://huggingface.co/karpathy/tinyllamas/resolve/main/stories15M.bin) и положить рядом со скриптом.

## Быстрый старт

Команды вводите по одной. Комментарии с `#` в zsh не вставляйте.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install numpy pyserial esptool

python esp_llm15.py info
python esp_llm15.py flash
python esp_llm15.py verify
python esp_llm15.py gen --prompt "Once upon a time"
```

- `info` показывает размер флеша и какие образы модели на него помещаются.
- `flash` выбирает прошивку под тип PSRAM и записывает модель (около минуты).
- `verify` сравнивает каждый режим прошивки с симулятором на Python бит в бит. Ждём `RESULT: PASS`.
- `mem` измеряет скорость чтения SRAM, PSRAM и флеша.
- `ladder` проходит всю лестницу оптимизаций и сохраняет `ladder15.json`. Занимает 20–30 минут, по пути несколько раз перепрошивает плату.
- `ladder --overclock` добавляет последнюю ступень: флеш и PSRAM на 120 МГц. Необязательно: если плата на этой частоте не стартует, скрипт пропустит ступень и вернёт обычную прошивку.
- `gen` генерирует текст на плате в самом быстром режиме.

Если esptool не может подключиться: зажмите BOOT, нажмите RESET, отпустите BOOT.

Без платы: `python esp_llm15.py analyze --model stories15M.bin` сравнивает качество всех приёмов сжатия.

## Режимы (флаги GEN)

| флаг | что делает |
| --- | --- |
| `k1` / `k2` | скалярный C / ассемблер PIE |
| `c1` / `c2` | одно / два ядра |
| `a1` | аппаратная автозагрузка кэша (autoload) для области модели |
| `a2` | ручная предзагрузка следующего куска весов в кэш (одно ядро) |
| `x1` | двухэтапный классификатор: 4-битный отбор 16 кандидатов, точный int8 пересчёт |
| `w1` | часть матриц скопирована в свободную SRAM |
| `p<k>` | самоспекуляция: k черновых токенов из n-грамм, проверка одним проходом |

Например, `python esp_llm15.py bench --modes k2c2,k2c2x1w1p3`.

## Состав

- `esp_llm15.py` — экспорт (GPTQ, обрезка словаря, n-граммы), симулятор Sim3 на numpy, прошивка, проверка, замеры.
- `firmware/main/llm3.c` — движок: int4-веса, int8-активации, самоспекуляция, двухэтапный классификатор.
- `firmware/main/mv_pie3.S` — матрично-векторные ядра на `ee.vmulas.s8.accx` без распаковки полубайтов (трюк ×16).
- `firmware/main/main3.c` — отображение модели из флеша в память, второе ядро, протокол по serial.
- `firmware/prebuilt/` — собранные варианты: `quad_c32`, `quad_c64`, `quad_c64f120`, `octal_c32`, `octal_c64`, `qemu`.
- `blobs/` — образы модели: `q4_v6144` (основной, 6.2 МБ), `q8_v4096` (int8 для сравнения, 7.1 МБ),
  `q8_v6144` (int8, нужен флеш 16 МБ).
- `data/aux15.npz` — частоты токенов, калибровочные и проверочные истории, корпус для n-грамм. Всё это сгенерировала сама float32-модель.
- `tok32k.bin` — токенизатор Llama-2 на 32 000 токенов; прошивка использует из него 6144.
- `test/` — тот же движок, собранный на компьютере, и его сравнение с симулятором.

## Проверка без платы

Цепочка проверки: симулятор на numpy ≡ движок на C на компьютере ≡ QEMU ≡ плата.
Первое звено можно повторить за секунды:

```bash
cd test
gcc -O2 -ffp-contract=off -o host3 host3.c ../firmware/main/llm3.c -lm
python compare3.py ../blobs/stories15M_q4_v6144.esp3 40
```

Ждём `ALL BIT-EXACT`. Флаг `-ffp-contract=off` обязателен: без него компилятор склеивает умножения со сложениями, и float-операции перестают совпадать с симулятором.

## Пересборка прошивки

ESP-IDF 5.3: `cd firmware && ./build_all.sh quad_c64` (результат в `prebuilt/quad_c64/`). Без аргументов собираются все варианты.

В `sdkconfig.defaults` обязательно `CONFIG_SPI_FLASH_ROM_IMPL=n`. С ROM-реализацией драйвера флеша отображение модели
через `esp_mmu_map` ломается: на плате прошивка пишет `NOMODEL` и `ESP_ERR_NO_MEM`, хотя свободных страниц MMU достаточно.
